◆ FinishSetup()

virtual void UnityEngine.InputSystem.InputBindingComposite.FinishSetup ( ref InputBindingCompositeContext context)
protectedvirtual

Called after binding resolution for an InputActionMap is complete.

Some composites do not have predetermine value types. Two examples of this are Composites.OneModifierComposite and Composites.TwoModifiersComposite, which both have a "binding" part that can be bound to arbitrary controls. This means that the value type of these bindings can only be determined at runtime.

Overriding this method allows accessing the actual controls bound to each part at runtime.

[InputControl] public int binding;
protected override void FinishSetup(ref InputBindingContext context)
{
// Get all controls bound to the 'binding' part.
var controls = context.controls
.Where(x => x.part == binding)
.Select(x => x.control);
}

Return the name of the control layout that is expected for the given part (e.g. "Up") on the given composite (e.g. "Dpad").

Paramètres
compositeRegistration name of the composite.
partName of the part.
Renvoie
The layout name (such as "Button") expected for the given part on the composite or null if there is no composite with the given name or no part on the composite with the given name.

Expected control layouts can be set on composite parts by setting the InputControlAttribute.layout property on them.

InputBindingComposite.GetExpectedControlLayoutName("Dpad", "Up") // Returns "Button"
// This is how Dpad communicates that:
[InputControl(layout = "Button")] public int up;
